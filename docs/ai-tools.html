AI Voice Agent

AI Tools Reference

The 14 server-side tools the AI agent can invoke during a call. Each is clinic-scoped and returns a structured { success, result, data } payload. Tools are dispatched by VapiToolDispatcher and named by the CallToolName enum.

Verification gate

Tools that read or modify patient data are protected — they require the caller's identity to be verified first (by confirming date of birth). If a protected tool is called before verification, it returns a prompt to identify the patient instead of running.

Protected tools
book_appointment, reschedule_appointment, cancel_appointment, verify_insurance, list_upcoming_appointments
!

A patient_id supplied in tool arguments is never trusted on its own. Identity is established only through a matching date of birth via lookup_patient or verify_identity — this protects PHI on phone, web, and chat sessions alike.

Identity & lookup

ToolPurpose
lookup_patientFind a patient by phone, name, and/or date of birth (caller ID is used automatically when no phone is provided). Sets the call's patient. Auto-verifies when a supplied DOB matches, or when no DOB is on file.
verify_identityConfirm a patient's date of birth to mark the call as verified. Accepts an explicit patient_id or uses the one already on the call.
create_patient_leadCreate a new patient record from a first/last name when no match is found — captures the caller as a lead and verifies them.

Scheduling

ToolPurpose
check_appointment_typesList the clinic's bookable appointment types and durations.
check_scheduleFind available slots for a provider/date.
book_appointmentBook an appointment. Performs an atomic conflict check to prevent double-booking a provider.protected
reschedule_appointmentMove an existing appointment to a new date/time.protected
cancel_appointmentCancel an appointment.protected
list_upcoming_appointmentsList the patient's upcoming appointments.protected

Insurance & triage

ToolPurpose
verify_insuranceRun an eligibility check against the patient's insurance via the configured gateway.protected
assess_urgencyEvaluate symptoms against triage rules/keywords and return an urgency level and recommended action.

Hand-off & follow-up

ToolPurpose
create_callback_taskCreate a staff callback task (categorized) so a human follows up.
transfer_callRecord a transfer request, create a high-priority callback task, and tell the caller a team member will follow up (also shares the clinic line).
send_smsQueue a text message as a front-desk task to be sent to the caller. (Hiro records the request; wire a real SMS provider to auto-send.)

Return shape

Every tool returns a consistent structure that the assistant reads back to the caller:

{
  "success": true,
  "result": "Found and verified patient: Jane Doe. Identity confirmed.",
  "data": { "patient_id": 42, "name": "Jane Doe", "verified": true }
}

On failure, success is false and the failure is tracked on the call. After two consecutive failures the agent offers a transfer (see Overview → escalation).

Extending tools

Tools are added in two places: register the name in the CallToolName enum and add a handler branch in VapiToolDispatcher::dispatch(). Sync the updated tool definitions to Vapi (saving the AI configuration, or php artisan vapi:sync-tunnel in local dev).
