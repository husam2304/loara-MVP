White-Label & Branding

Hiro is built to be rebranded. The product name flows from a single source to the entire UI, and clinics can apply their own logo and favicon.

Product name

The application name is resolved once and shared to every page via the appName Inertia prop. Resolution order:

  1. The branding app name set in Platform → Settings (a PlatformSetting), if present.
  2. Otherwise APP_NAME from .env / config('app.name').

That single value drives:

  • The sidebar logo text (clinic and platform panels).
  • Browser tab titles — a global Inertia title callback appends the app name to every page.
  • Auth screens (login, register, password reset) and the public landing page.
  • SMTP test emails and the landing-page footer/copyright defaults.
# .env
APP_NAME="Acme Reception AI"
ℹ

Set the name in Platform → Settings to change branding without editing .env or rebuilding. Either way, no code changes are required.

Logo & favicon

Each clinic can upload its own logo and favicon from Settings → Clinic (validated image types and size). These are stored per clinic and shown in that clinic's panel.

Landing page

The public marketing page is fully content-managed per clinic via the landing-page CMS — hero, features, pricing, CTA, footer, and more — so each tenant can present its own brand.

Theme & colors

The UI is styled with Tailwind CSS v4 using CSS variables/tokens. Adjust the palette in the Tailwind theme / CSS token definitions and rebuild:

npm run build

Error & installer pages

Custom error pages (404/403/419/429/500/503) and the web installer display config('app.name'). The installer chrome shows the product name "Hiro" by design, since it runs before a buyer has set their brand; rename it in resources/views/install/ if you wish.

Extending integrations (connectors)

The integrations module records connections and sync history. To make a sync pull real data from a provider (EHR, calendar, etc.), implement the provider call inside IntegrationSyncService::runProviderSync() — it is the single extension point and already writes structured sync-log entries (records processed/failed, status, timestamps).
