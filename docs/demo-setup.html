Live Demo Setup

A reviewer (or prospective buyer) must be able to experience the AI agent actually answering, not just read about it. This page gets a public, reviewer-ready demo running — including the one-command Vapi provisioning helper.

★

The fastest reviewer path is an in-browser web call — no phone number to buy. The command below wires the assistant; the reviewer then clicks "test call" inside the app.

Prerequisites

  • A publicly reachable demo URL over HTTPS (Vapi webhooks require it).
  • A Vapi account with call balance, and your keys.
  • (Optional, for the billing demo) Stripe test-mode keys.

Step 1 — Configure the environment

In .env on the demo server:

APP_ENV=production
APP_DEBUG=false
APP_NAME="Your Brand"
APP_URL=https://demo.your-domain.com

VAPI_PRIVATE_KEY=your-private-key
VAPI_PUBLIC_KEY=your-public-key
VAPI_SERVER_SECRET=a-long-random-string
VAPI_WEBHOOK_URL=https://demo.your-domain.com/api/webhooks/vapi
!

APP_DEBUG must be false — a stack trace shown to a reviewer is a common rejection reason. Set APP_NAME so the white-label shows your brand, not "Laravel".

Apply the config and build assets:

php artisan config:clear
npm run build

Step 2 — Seed demo data

php artisan migrate:fresh --seed

This creates two clinics with realistic patients, providers, calls, and appointments, plus the demo logins:

RoleEmailPassword
SuperAdmin (platform)hiro@mail.compassword
Clinic owner (Enterprise — all features)clinic@mail.compassword

Step 3 — Provision the live AI assistant

One command creates the demo clinic's Vapi assistant, syncs its function tools, and points it at your webhook:

php artisan hiro:demo-setup

To also provision a free, callable Vapi phone number linked to the assistant:

php artisan hiro:demo-setup --phone --area-code=415

Useful options:

OptionEffect
--freshWipe and reseed the database first.
--phoneProvision a free Vapi phone number for the demo assistant.
--area-code=NNNPreferred US area code for the free number.

The command prints the assistant ID, any phone number, the demo logins, and a final checklist. It refuses to run (with guidance) if VAPI_PRIVATE_KEY is missing.

ℹ

Re-running is safe — it updates the existing assistant instead of creating duplicates.

Step 4 — Register the Vapi webhook

In Vapi, point the assistant's server URL at https://demo.your-domain.com/api/webhooks/vapi and set the secret to your VAPI_SERVER_SECRET. The provisioning command already sets the assistant's server URL from VAPI_WEBHOOK_URL. See Webhooks.

Step 5 — Verify the AI answers

  1. Web call — log in as clinic@mail.com, open Settings → AI Assistant, and use the in-browser test-call widget (needs VAPI_PUBLIC_KEY). Talk to the assistant.
  2. Phone call — if you provisioned a number, dial it and book a test appointment by voice.
  3. Confirm capture — open Call Center and verify the call, transcript, and tool invocations were recorded.

Step 6 — (Optional) Billing demo

  1. Add Stripe test-mode keys to .env.
  2. In Platform → Pricing, sync plans to Stripe.
  3. Add a Stripe webhook to /api/webhooks/stripe.
  4. Show a checkout using Stripe's test card 4242 4242 4242 4242.

Reviewer script

Give the reviewer a short path so they see the value in 2 minutes:

  • Log in as clinic@mail.com → Dashboard (live metrics) → Call Center.
  • Settings → AI Assistant → start a web call → ask to book an appointment.
  • Return to Call Center → open the call → transcript & tools.
  • Workflow → see the multi-assistant builder. Analytics → real charts.
  • Log out → log in as hiro@mail.com → Platform panel (clinics, plans, settings).

Pre-submit checklist

  • ☐ APP_DEBUG=false, APP_ENV=production, APP_NAME = your brand.
  • ☐ HTTPS active; demo URL public.
  • ☐ php artisan hiro:demo-setup ran successfully; assistant ID shown.
  • ☐ Web call works (or phone number answers).
  • ☐ Vapi webhook registered with matching secret; tools resolve.
  • ☐ Queue worker + scheduler running (reminders, jobs).
  • ☐ Both demo logins work; data looks realistic.
  • ☐ (If showing billing) Stripe test keys + webhook configured.
  • ☐ Clicked every sidebar page — no errors, no "coming soon".
