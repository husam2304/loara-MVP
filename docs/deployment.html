Operations

Deployment

Take Hiro from a working install to a production-ready deployment: secure config, built assets, a queue worker, the scheduler, and reachable webhooks.

1. Production environment

APP_ENV=production
APP_DEBUG=false
APP_URL=https://app.example.com
!

Never run production with APP_DEBUG=true — errors would expose stack traces and configuration to visitors.

2. Optimize & build

composer install --no-dev --optimize-autoloader
php artisan config:cache
php artisan route:cache
php artisan event:cache
npm install && npm run build
php artisan storage:link
ℹ

storage:link exposes uploaded logos/favicons. Re-run config:cache whenever you change .env.

3. Queue worker

Hiro uses the database queue driver by default. Run a worker (via Supervisor, systemd, or your platform's process manager):

php artisan queue:work --tries=3 --max-time=3600

Example Supervisor program:

[program:hiro-worker]
command=php /var/www/hiro/artisan queue:work --tries=3 --max-time=3600
autostart=true
autorestart=true
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/hiro/storage/logs/worker.log

4. Scheduler (cron)

Add Laravel's scheduler to cron. It runs appointments:send-reminders every minute to email upcoming-appointment reminders.

* * * * * cd /var/www/hiro && php artisan schedule:run >> /dev/null 2>&1
ℹ

PM2 alternative. The repo ships ecosystem.config.cjs at its root, which runs both the queue worker (queue:work) and the scheduler (schedule:work, no crontab needed) as managed processes:

pm2 start ecosystem.config.cjs
pm2 save && pm2 startup        # persist across reboots
pm2 reload ecosystem.config.cjs  # zero-downtime reload after each deploy

Use either Supervisor + cron or PM2 — not both — so reminders are dispatched and processed exactly once.

5. HTTPS & web root

  • Point your web server's document root at public/.
  • Serve over HTTPS — required by Stripe and Vapi webhooks.

6. Configure webhooks

Register both webhook endpoints with the respective providers (they must be publicly reachable over HTTPS):

ProviderEndpointSecret
Vapi/api/webhooks/vapiVAPI_SERVER_SECRET
Stripe/api/webhooks/stripeSTRIPE_WEBHOOK_SECRET

See Webhooks.

7. First-run / updates

On a fresh server you can either use the web installer or run migrations manually. After deploying an update, run pending migrations and rebuild caches:

php artisan migrate --force
php artisan config:cache && php artisan route:cache
npm run build

Deployment checklist

  • APP_DEBUG=false, APP_ENV=production, valid APP_KEY.
  • Assets built (npm run build); storage:link created.
  • Queue worker running; scheduler cron installed.
  • HTTPS active; both webhooks registered and verified.
  • APP_NAME set to your brand (see White-Label).
