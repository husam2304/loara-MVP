Core Concepts

Roles & Multi-Tenancy

Every clinic is an isolated tenant. Access is controlled by a six-value role enum plus per-plan feature flags.

The tenant model

A Clinic is the tenant. Almost every record — patients, appointments, calls, providers, insurance, integrations, workflows — carries a clinic_id. All clinic-scoped queries filter by the authenticated user's clinic, and route-model-bound records are verified to belong to that clinic before any action.

ℹ

SuperAdmins are not attached to any clinic (clinic_id = null); they operate exclusively in the platform panel.

User roles

Defined by the UserRole enum:

RoleValueScope
SuperAdminsuper_adminPlatform operator. Manages all clinics, plans, and global settings.
Clinic Ownerclinic_ownerFull access within their clinic, including admin/users, billing, workflows, and settings.
ProviderproviderClinical staff — appointments, patients, calls.
StaffstaffFront-desk staff — day-to-day operations.
BillingbillingBilling & subscription management.
CustomercustomerPatient-facing. Limited to Dashboard + Billing — intentionally excluded from clinical/PHI routes (call center, appointments, patients, insurance, analytics).

Gating with middleware

Routes are protected by composable middleware (see Architecture):

// Owner-only, requires an active subscription
Route::middleware(['role:clinic_owner', 'subscribed'])->group(...);

// Operational/clinical routes — clinic staff only, subscription required.
// The patient-facing `customer` role is intentionally excluded so it cannot read PHI.
Route::middleware(['role:clinic_owner,provider,staff,billing', 'subscribed'])->group(...);

// Feature-gated (plan must include the flag)
Route::middleware('feature:custom_workflows')->group(...);

Plan feature flags

Beyond roles, access to certain modules depends on the clinic's plan. Feature flags live on each PlanConfiguration and are enforced by the feature: middleware via FeatureGateService:

FlagUnlocks
advanced_analyticsEnhanced analytics access.
triageTriage rules module.
integrationsThird-party integrations.
custom_workflowsVisual workflow (squad) builder.

Other flags (ai_calls, appointment_booking, sms, campaigns, priority_support) describe plan inclusions surfaced in the UI. Plan/feature mapping is editable in Platform → Pricing.

Clinic enable / disable

A platform admin can disable a clinic. Disabled clinics are blocked at login and any active session is logged out by the clinic_enabled middleware. SuperAdmins are unaffected.

Impersonation

Two impersonation paths exist, each preserving an audit trail and a one-click return:

  • SuperAdmin → clinic from the platform panel (to support a tenant).
  • Clinic Owner → clinic staff within their own clinic.

The original administrator is restored on logout. See Platform Admin.

New-tenant provisioning

When a clinic registers, ClinicProvisioner creates the baseline records a tenant needs to operate: an AI assistant configuration, a full week of operating hours, reminder settings, and the owner's notification preferences. This guarantees a usable starting state immediately after signup.
